OpenRakis

A work-in-progress reverse-engineering project for Cryo Interactive's DUNE (1992 DOS). Combines x86 assembly analysis, a ScummVM engine implementation, a cross-platform save-file editor, and data-extraction utilities — all under GPLv2.

GPLv2 C# · .NET 8 C++ x86 ASM ScummVM Linux · macOS · Windows

Overview

DUNE (1992) is an adventure / strategy game developed by Cryo Interactive Entertainment and published by Virgin Games, loosely based on Frank Herbert's novel. It shipped in two builds: a floppy edition and a CD edition that adds full speech and video sequences.

OpenRakis documents the game's binary formats, reconstructs its internal logic from 16-bit x86 DOS assembly, and provides a playable engine inside ScummVM. The project targets the PC DOS versions of the game.

No copyrighted game data is distributed. The original game binaries and data files are copyrighted by their respective owners and are not included in this repository. You must own a copy of the game to use these tools.

Components

DuneEdit2

Cross-platform GUI and CLI save-file editor for the CD version. Reads, decompresses, modifies, and recompresses .SAV save game files. Displays every parsed field: generals, NPCs, troops, locations, smugglers, traps, game stage, and more.

C# / .NET 8 Avalonia UI 11 GUI + CLI Win / macOS / Linux
ScummVM Engine

C++ engine plugin for ScummVM that loads game archives, renders graphics, plays HNM video sequences, and decompresses HSQ-compressed data files. Detects both the floppy and CD game versions.

C++ ScummVM API HNM playback HSQ decompression
Data Extraction Suite

Command-line tools to unpack DUNE.DAT, repack modified files, and manipulate lip-sync data inside VOC audio files. Enables inspection and modification of all game assets.

C# / .NET 8 DUNE.DAT VOC / LIP CLI
Assembly Archive

Commented x86 16-bit real-mode assembly of the original DOS executables, produced with IDA Freeware and Ghidra. Serves as the ground truth for the C# reimplementation in Cryogenic.

x86 ASM IDA Ghidra 16-bit DOS

Tools

Included Tools (tools/cd/)

  • DuneEdit2 Save-file editor with Avalonia GUI and a full command-line interface. Supports reading, writing, compressing, and decompressing .SAV files for the PC CD DOS version.
  • DuneExtractor Decompresses and extracts every file stored inside DUNE.DAT, the main game archive of the CD version, into a directory tree.
  • DuneImpactor Inverse of DuneExtractor. Re-creates a DUNE.DAT from a previously extracted directory tree, allowing round-trip asset modification.
  • LipsExtractor Copies the lip-sync data block from the header of Cryo's VOC audio files into separate .LIP files for analysis or editing.
  • LipsInjector Writes data from .LIP files back into the appropriate header offset of VOC files, enabling lip-sync modification.
  • UnHsq Standalone command-line decompressor for Cryo's HSQ format, translated from the ScummVM engine's HSQ implementation.
  • DuneSaveDescriptor Prints a human-readable description of every field in a save file to standard output, useful for debugging the save-file format.

DuneEdit2 Command-Line Reference

Usage: DuneEdit2 [options]

  -i, --InputFile      Required. Path to the save game file, e.g. DUNE37S1.SAV
                       (multiple files accepted for read-only mode).
  -o, --OutputFile     Output file name after Compress or Write.
  -r, --Read           (default: true) Print a description of the save game.
  -u, --Uncompress     Save the uncompressed save game as [file].UNCOMPRESSED.
  -c, --Compress       Compress the specified file.
  -w, --Write          Write one or more hex bytes at specific offsets, then
                       recompress. Format: 0xVALUE,0xOFFSET ...
  -p, --PauseBeforeExit Wait for a keypress before exiting.
  --help               Display help.
  --version            Display version information.

Example: patch a single byte at offset 0x1A to 0xFF and save the result: 

DuneEdit2 -i DUNE37S1.SAV -o OUT.SAV -w 0xFF,0x1A

External Reverse-Engineering Tools

  • IDA Freeware Disassembler used to produce the initial annotated assembly. IDA settings: 8086 16-bit Real Mode, entry point CS = 0x1ED.
  • Ghidra NSA's open-source reverse-engineering suite. Used alongside the Spice86 Ghidra code generator to emit C# stub functions from the disassembly.
  • UNLZEXE Unpacks LZEXE-compressed DOS executables. Required to unpack LOGO.EXE before disassembly.
  • DOSBox Debugger with AUTOEXEC A patched DOSBox build that accepts AUTOEXEC scripts, enabling scripted debugging sessions. Typical usage:
    Z:\DEBUG.COM DNCDPRG.EXE ENG ADP220 SBP2227 EMS 386 SAF WRIC:\DUNECD\
  • Chani (Simulfow Debugger) A flow-simulation debugger for DOS programs, useful for tracing execution paths through the original DUNE code.

File Formats

The CD version of DUNE uses several proprietary Cryo Interactive formats. The table below summarises what is known and what is implemented in this project.

Format Extension(s) Description Implemented?
DUNE.DAT .DAT Main archive containing all game assets (compressed). Extracted by DuneExtractor, repacked by DuneImpactor. ✔ Read & Write
HSQ .HSQ, various Cryo's in-house compression format used for most data files inside the archive. Header contains uncompressed length and a checksum. ✔ Decompress (ScummVM & UnHsq)
HNM .HNM Cryo's proprietary video format (HNM version 1). Contains interleaved audio and delta-coded video frames. See MultimediaWiki description. ✔ Playback (ScummVM engine)
SAV .SAV HSQ-compressed binary save game. Stores game state at a byte level including character attributes, troop positions, game stage, and dialogue flags. ✔ Read & Write (DuneEdit2)
VOC + LIP .VOC Standard Creative Labs VOC audio files, with a Cryo-specific lip-sync data block prepended in the header. Managed by LipsExtractor/LipsInjector. ✔ LIP extraction & injection
HERAD embedded Cryo's AdLib / OPL2 music driver format used in the DOS version. See VGMPF description and adplug implementation. Partial (referenced)
Palettes / sprites inside DAT Paletted bitmap data referenced in the partial data-files description. Decoded by the ScummVM graphics module. Partial (ScummVM engine)

Save-File Internals

DuneEdit2 exposes every parsed field from the CD save file. The following categories of data are currently decoded:

Generals

Player character state: charisma, contact distance, current game stage, and attribute flags.

NPCs

Per-NPC data: identity, current status, and any flags controlling dialogue availability.

Troops

Each military unit's location, equipment level, and task assignment.

Locations

Map sietch metadata: name reference, region index, and associated flags.

Smugglers

Smuggler network state and availability flags.

Traps

Trap/obstacle placement data stored in the save binary.

Game Stage

Current story progress flag used to gate quests, cutscenes, and NPC conversations.

Dissatisfaction

Per-region dissatisfaction values that influence troop morale and mission outcomes.

Reverse-Engineering Approach & Status

The project follows a layered strategy, moving from raw binary analysis to a fully portable C# reimplementation:

  1. Disassembly — IDA Freeware and Ghidra produce annotated 16-bit x86 assembly of DNCDPRG.EXE and DUNE.EXE. The results are committed to asm/.
  2. Live debugging — DOSBox Debugger and Chani trace execution at runtime to correlate data structures with disassembled code.
  3. Spice86 emulation — The original DOS executable runs inside Spice86, which exposes every memory access and I/O operation. Assembly functions are progressively overridden by C# equivalents.
  4. Cryogenic reimplementation — Each overridden C# function is committed to the Cryogenic repository, building toward a full, dependency-free C# reimplementation.
  5. ScummVM engine — In parallel, a C++ ScummVM engine plugin reproduces the game using ScummVM's cross-platform infrastructure.

Building and Testing (C# tools)

# Run all unit tests
cd tools/cd
dotnet test --configuration Release

# Build self-contained binaries for all platforms
dotnet publish -c Release -r linux-x64 --self-contained true -o Release/linux
dotnet publish -c Release -r win-x64  --self-contained true -o Release/windows
dotnet publish -c Release -r osx-x64  --self-contained true -o Release/macos

CI / Releases

Every push to master triggers a GitHub Actions workflow that:

  1. Runs the unit test suite (dotnet test).
  2. Publishes self-contained binaries for Linux x64, Windows x64, and macOS x64.
  3. Creates a pre-release tagged latest on GitHub Releases, containing a Release.zip with all three platform builds.

Areas Where Contributions Help Most

  • Annotating additional functions in the disassembled asm/ files.
  • Extending DuneEdit2 to decode remaining unknown save-file fields.
  • Completing audio support — implementing the HERAD music driver.
  • Improving the ScummVM engine's graphics and game-logic coverage.
  • Adding floppy-version tooling parity with the CD tools.
  • Documentation of any additional file formats found inside DUNE.DAT.
